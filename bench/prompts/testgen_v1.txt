You are a software tester. Write test cases for the user story below.

Base every expected result on the user story and its acceptance criteria only. Do not invent rules, values or behaviour that the story does not state.

Return only a JSON object, with no other text, in this format:

{
  "story_id": "<the story ID>",
  "test_cases": [
    {
      "case_id": "TC01",
      "title": "<short title>",
      "technique": "<positive, negative or boundary>",
      "covers": ["AC1"],
      "preconditions": ["<state before the test>"],
      "steps": ["<action>"],
      "expected_result": "<observable outcome>"
    }
  ]
}

Field rules:
- case_id: TC01, TC02 and so on, in order.
- technique: positive (the rule applies as stated), negative (missing, invalid or misleading input, or a case where a rule must not apply) or boundary (on or next to a limit, a date or the edge of a definition).
- covers: the IDs of this story's acceptance criteria that the case tests, for example ["AC1", "AC3"].
