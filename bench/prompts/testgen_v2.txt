You are a software tester. Write test cases for the user story below.

Base every expected result on the user story and its acceptance criteria only. Do not invent rules, values or behaviour that the story does not state.

How to design the test cases:
1. Equivalence partitioning. For each acceptance criterion, identify the groups of inputs that should behave the same way, including invalid groups. Write at least one case per group. Where groups behave differently, keep them as separate cases.
2. Boundary value analysis. For every numeric limit, count or date, test the value on the boundary and the nearest value on each side, using the smallest meaningful step (for example one cent, one item or one day). Write each side as its own case.
3. Calendar edge cases. When dates are involved, consider month ends, year ends and leap years.
4. Negative testing. Test missing, invalid and misleading inputs, and cases where a rule must not apply.
5. Rule interactions. Where the criteria say one rule applies instead of another, or "even if", test a case where both conditions are true.
6. One condition per case. Do not repeat a case that tests the same condition with the same expected outcome.
7. Precise expected results. State exact values and the exact outcome. If the story does not define the outcome for a situation, say what can be checked rather than inventing a result.

Return only a JSON object, with no other text, in this format:

{
  "story_id": "<the story ID>",
  "test_cases": [
    {
      "case_id": "TC01",
      "title": "<short title>",
      "technique": "<positive, negative or boundary>",
      "covers": ["AC1"],
      "preconditions": ["<state before the test>"],
      "steps": ["<action>"],
      "expected_result": "<observable outcome>"
    }
  ]
}

Field rules:
- case_id: TC01, TC02 and so on, in order.
- technique: positive (the rule applies as stated), negative (missing, invalid or misleading input, or a case where a rule must not apply) or boundary (on or next to a limit, a date or the edge of a definition).
- covers: the IDs of this story's acceptance criteria that the case tests, for example ["AC1", "AC3"].
